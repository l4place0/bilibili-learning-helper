## ADDED Requirements

### Requirement: Unified question type schema
The system SHALL define a unified JSON schema for all question types with shared base fields and type-specific extensions. Base fields: id, type, difficulty (1-5), bloom_level, source_refs (segment IDs), frame_ref (optional).

#### Scenario: Question type schema validation
- **WHEN** a question object is generated by the LLM
- **THEN** it contains all required base fields (id, type, difficulty, bloom_level, source_refs)
- **AND** it contains type-specific extension fields as defined by the question type

### Requirement: Generate true/false questions
The system SHALL generate true/false questions with statement, correct boolean, and explanation fields.

#### Scenario: True/false question from transcript
- **WHEN** the LLM generates a true/false question
- **THEN** the question contains a statement that is either true or false
- **AND** the explanation references the source transcript segments

### Requirement: Generate multiple choice questions
The system SHALL generate multiple choice questions with 4 options, one correct answer, and explanation.

#### Scenario: Multiple choice question with distractors
- **WHEN** the LLM generates a multiple choice question
- **THEN** it contains exactly 4 options with 1 correct answer
- **AND** distractors are plausible but incorrect based on the transcript

### Requirement: Generate fill-in-the-blank questions
The system SHALL generate fill-in-the-blank questions with a template containing blanks and expected answers.

#### Scenario: Fill-in-the-blank from key terms
- **WHEN** the LLM generates a fill-in-the-blank question
- **THEN** the template has 1-3 blanks marked with `___`
- **AND** each blank has an expected answer (case-insensitive matching)

#### Scenario: Fill-in-the-blank auto-grading
- **WHEN** a user submits an answer to a fill-in-the-blank question
- **THEN** the system compares against expected answers (case-insensitive, trimmed)
- **AND** shows correct/incorrect feedback immediately

### Requirement: Generate sequencing questions
The system SHALL generate sequencing questions where items must be ordered correctly.

#### Scenario: Step ordering from tutorial content
- **WHEN** the content type is tutorial and the LLM generates a sequencing question
- **THEN** the question contains 4-6 items in scrambled order
- **AND** the correct_order array defines the right sequence

### Requirement: Generate matching questions
The system SHALL generate matching questions with concept-definition pairs.

#### Scenario: Matching question from technical content
- **WHEN** the LLM generates a matching question
- **THEN** it contains 4-6 pairs of {left, right} items
- **AND** the left column is scrambled in the presentation

### Requirement: Generate code completion questions
The system SHALL generate code completion questions with context code, a missing section, and the expected answer.

#### Scenario: Code completion from tutorial with code
- **WHEN** the content type is tutorial and the video contains code
- **THEN** the LLM generates a code completion question with language-specific context
- **AND** the missing code section is the key logic (not boilerplate)

### Requirement: Generate scenario-based questions
The system SHALL generate scenario questions that present a situation and ask for a solution, with sample answer and key evaluation points.

#### Scenario: Scenario question from applied content
- **WHEN** the LLM generates a scenario question
- **THEN** it contains a realistic scenario description, a specific question, a sample_answer, and 3-5 key_points for self-evaluation

### Requirement: Generate "explain in your own words" questions
The system SHALL generate open-ended explanation questions that ask the user to explain a concept without looking at the answer.

#### Scenario: Self-explanation question
- **WHEN** the LLM generates an explanation question
- **THEN** it specifies the concept to explain and provides evaluation_criteria
- **AND** the answer is hidden until the user submits their explanation (self-assessment)

### Requirement: Generate comparative analysis questions
The system SHALL generate comparison questions that ask about similarities and differences between two concepts from the video.

#### Scenario: Comparison question from multi-concept content
- **WHEN** the video discusses two or more related concepts
- **THEN** the LLM generates a comparison question asking about their differences
- **AND** the answer includes a structured comparison (similarities + differences)

### Requirement: Generate visual questions from frames
The System SHALL generate questions that reference keyframes, asking the user to interpret visual content.

#### Scenario: Frame-based question from code screenshot
- **WHEN** a keyframe contains code or a diagram
- **THEN** the LLM generates a question asking the user to explain or analyze the visual content
- **AND** the question references the frame and the nearest transcript segment

### Requirement: Auto-select question types by content type
The system SHALL automatically select appropriate question type combinations based on the video's content_type.

#### Scenario: Tutorial generates step-based questions
- **WHEN** the content type is tutorial
- **THEN** the system prioritizes: fill-in-the-blank, code completion, sequencing, scenario questions

#### Scenario: Tech talk generates concept-based questions
- **WHEN** the content type is tech_talk
- **THEN** the system prioritizes: multiple choice, comparison, explanation, true/false questions

### Requirement: Generate 15-20 questions per video
The system SHALL generate 15-20 questions per video, covering 3-4 different question types.

#### Scenario: Question count and variety
- **WHEN** a video summary is complete and the question generation prompt runs
- **THEN** the output contains 15-20 questions
- **AND** at least 3 different question types are represented

### Requirement: Question generation as separate LLM call
The system SHALL run question generation as a separate LLM call after summarization, not merged into the summary prompt.

#### Scenario: Question generation after summary
- **WHEN** a video summary is generated
- **THEN** the system makes a second LLM call with the summary + formatted segments as input
- **AND** the summary quality is not affected by question generation instructions

### Requirement: Review Doc renders multiple question types
The system SHALL render different question types with appropriate interactive UI components in the Review Doc.

#### Scenario: Mixed question type deck
- **WHEN** a Review Doc is generated with questions of multiple types
- **THEN** each question renders with type-appropriate UI (flip card, multiple choice buttons, text input for fill-in-blank, drag-to-reorder for sequencing, etc.)

#### Scenario: Question type filter
- **WHEN** a user opens the Cards tab in Review Doc
- **THEN** they can filter questions by type (e.g., show only fill-in-the-blank)

### Requirement: SM-2 scheduling applies to all question types
The system SHALL apply SM-2 spaced repetition scheduling to all question types, not just Q&A cards.

#### Scenario: Non-QA card tracks SM-2 state
- **WHEN** a user answers a fill-in-the-blank or multiple choice question
- **THEN** the SM-2 algorithm schedules the next review based on the quality rating
- **AND** the scheduling state is persisted in localStorage
